The project is documented at fireflyk64.github.io/wcmulti.

hackernews · daniel\_rh · Nov 4, 18:51 · [Discussion](https://news.ycombinator.com/item?id=50369895)

**「Background」** Wing Commander is a classic space combat game that runs in DOS, where the game state is confined to a 64k data segment. **「Impact」** Players can now fly Wing Commander&\#x27;s story missions cooperatively, a mode the original game did not offer. The co-op mode depends on the author&\#x27;s injected calls and network state synchronization, so it is not a drop-in patch for the original DOS executable.

### [Russian-linked hackers exploited patched iOS and Android flaws in mobile espionage campaign](https://arstechnica.com/security/2026/11/hackers-exploited-ios-and-android-flaws-to-infect-phones/) ⭐️ 7.0/10

Researchers reported Wednesday that hackers assessed with moderate to high confidence to be Russia&\#x27;s Foreign Intelligence Service exploited previously patched iOS and Android flaws to infect visitors of multiple websites, including america250.org, which commemorates the 250th anniversary of American independence. The attack chain began when iPhone or Android users visited one of potentially hundreds of sites; injected JavaScript profiled the device, then delivered platform-tailored payloads that attempted to steal browser cookies and, in some cases, Wi-Fi passwords and full mobile device data. The attackers registered america250\[.\]holiday as a reverse proxy to the real america250.org, serving its content with added malicious JavaScript.

rss · Ars Technica · Nov 4, 22:26

**「Background」** The campaign relies on a technique known as &quot;watering hole&quot; attacks, in which attackers compromise or impersonate websites likely to be visited by their targets and inject malicious JavaScript into the page. The JavaScript profiles each visiting device and then delivers a platform-specific payload, exploiting previously patched vulnerabilities in iOS and Android. This approach is a common tactic in state-sponsored espionage, allowing attackers to reach specific individuals without requiring them to click a malicious link in an email or message.

**「Impact」** Users who visited the compromised sites on unpatched iOS or Android devices risked having browser cookies, Wi-Fi passwords, and full device data exfiltrated; because the exploited flaws were already patched, installing the latest OS updates is the direct mitigation.

The optimization, reported by InfoQ on November 5, 2026, is a concrete engineering achievement, but implementation details and independently measured results are not yet available.

rss · InfoQ 人工智能 · Nov 5, 09:00

**「Background」** Consistent hashing is a distributed systems technique that maps keys to nodes so that only a small fraction of mappings change when nodes are added or removed, making it a common choice for routing requests across CDN edge servers. At Cloudflare&\#x27;s scale, the data structures used to maintain these mappings can consume substantial memory, which is why optimizing them can yield savings on the order of 100 TB.

**「Memory footprint reduced by 100 TB」** For Cloudflare, the optimization reduces worldwide memory usage by more than 100 TB, lowering memory pressure on the Pingora Backend Router that routes requests to caches. The savings come from Rust memory optimizations in pingora-ketama, where the original Point struct stored a 32-bit hash and an index. Because the change is in an internal service, it does not require any action from Cloudflare customers.

### [Looped transformer weight sharing saves storage but not HBM traffic on B200](https://www.reddit.com/r/MachineLearning/comments/1xnskvt/do_looped_transformers_save_hbm_traffic_profiling/) ⭐️ 7.0/10

Profiling on an NVIDIA B200 with Nsight Compute shows that looped transformers&\#x27; shared weights do not reliably stay in cache, so weight reuse saves storage but not necessarily HBM traffic. A chain of eight matmuls with one shared 72 MiB weight ran 24% faster than the same chain with eight identical copies and read almost nothing from HBM, but at 288 MiB—larger than L2—the difference disappeared. In a full Huginn Core with random weights, eight iterations took about eight times as long as one and read about eight times as much data from HBM. The measured result means sharing alone does not stop the GPU from re-reading weights from HBM at every iteration.

reddit · r/MachineLearning · /u/2dayyy6 · Nov 4, 16:26

**「Background」** Looped transformers such as Huginn reuse the same weight matrices at every iteration, so in principle the GPU could keep those weights in on-chip cache and avoid re-reading them from HBM on each pass. Whether that reuse actually reduces HBM traffic depends on whether the shared weights fit in L2 between iterations; on the B200, a 72 MiB shared weight fits, but a 288 MiB weight set does not.

**「Impact」** For developers optimizing transformer inference on GPUs, the practical consequence is that looped weight sharing only reduces HBM traffic when the shared weights fit in L2; otherwise each iteration still re-reads them from HBM, so memory bandwidth savings do not scale with iteration count.
